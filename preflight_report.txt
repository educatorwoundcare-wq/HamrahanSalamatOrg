Source Inventory:
- Entities.kt: Contains all Room entity definitions.
- HamrahanDao.kt: Data access object for all operations.
- HamrahanRepository.kt: Exposes domain operations and calls registerLocalChange.
- SyncEngine.kt: Handles sync loops and conflict resolution.

- WorkspaceManager.kt: Workspace state management.
- RegisterServiceAndGenerateLedgerUseCase.kt: Complex transaction usecase.
- SettleEmployeeCommissionUseCase.kt: Another transaction usecase.

Entity UUID Coverage:
- Most entities (Patient, Employee, Service, etc.) already have `val uuid: String = java.util.UUID.randomUUID().toString()`.
- The following synchronized entities LACK UUIDs and currently use `id.toString()` or `key`:
  - FinancialReport (id: Int)
  - SystemSetting (key: String)
  - AuditLog (id: Int)
  - UserPermission (permissionName: String)
  - FinancialEditHistory (id: Int)
  - JournalEntry (id: Int)
  - SyncMetadata (does not need UUID, will be replaced)
  - CloudSyncRecord (legacy, uses type_id)

Room Transaction Coverage:
- `RegisterServiceAndGenerateLedgerUseCase` and `SettleEmployeeCommissionUseCase` use `dao.runInTransaction`.
- `HamrahanRepository` uses `dao.runInTransaction` extensively.
- However, `registerLocalChange` is called *after* or inside the transaction but it performs a separate insert. `registerLocalChange` internally calls `dao.insertSyncMetadata(meta)` and `syncEngine.triggerSync()`.

SyncMetadata References:
- Used heavily in `registerLocalChange` and `reindexWorkspaceData` and `SyncEngine`.
- Needs to be replaced with `SyncQueue`.

SyncQueue References:
- Existing `SyncQueue` data class is currently partially defined but not fully used as the canonical operation log in all mutations (currently `SyncMetadata` is used).

registerLocalChange References:
- Called extensively in `HamrahanRepository.kt`, `HamrahanViewModel.kt`, `RegisterServiceAndGenerateLedgerUseCase.kt`, `SettleEmployeeCommissionUseCase.kt`.

reindexWorkspaceData References:
- Called in `HamrahanViewModel.kt` during workspace join.
- Re-marks all entities as pending.

cloud_records References:
- Defined in `Entities.kt`, used in `CloudClient` or `SyncEngine`.
